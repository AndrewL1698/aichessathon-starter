# nnue h256-52m-res — `weights/nnue-h256-52m-res.npz` (residual)

The first **residual** net: the output is a correction added to the hand evaluation, not an
evaluation on its own. Pipeline commit 5e4e9a6; hand evaluation from `fasteval.py` and
`fastboard.py` at origin/prod **8b0d4d0**, unmodified.

## Why

The plain nets lose to the hand evaluation in play (engine session's gauntlet at 10s+0.1s vs
v3.1, runtime exact, 1.85M vs 2.41M nodes/s): nnue.npz 35.2% over 64 games, h256-e87 43.0%,
h256-52m 48.1% at 27 games. Over 1,393 random-playout positions the plain net's score has
slope 0.64 and r=0.71 against material where the hand evaluation has 1.00 / 0.98: it is
accurate on lichess-style positions and noisy on the ones a search reaches. A residual net
keeps the hand evaluation's material sanity by construction and learns only the correction.

## Formulation

`train.py --target residual` fits `sigmoid((hand + net) / 400)` to `sigmoid(cp / 400)`, the
same loss as every other run here. That is the residual in WDL space rather than a net fitted
to `cp - hand` directly; the two agree except at the ±2000 clip, where 20% of rows sit and a
raw difference would teach the net to pull won positions back toward 2000. Runtime is the
same either way: **eval = hand + raw × 400**. The npz carries `target = "residual"`.

## Data

The 90M rows of [h256-52m](h256-52m.md) with one extra int16 array, `hand`, from
`tools.nnue.hand` (141 s for all 90M rows). The position is rebuilt from the feature row and
evaluated with White to move; that equals the fen path exactly because the evaluation is
colour-symmetric and uses no castling, en passant or counters: **20,000 real records, 0
mismatches** (`--verify`).

Baselines on the 2% split (1.8M rows):

| predictor | val loss |
|---|---|
| mean of the target | 0.055503 |
| hand evaluation alone (net = 0) | 0.032934 |
| best plain net, h256-52m-e60, same split | 0.014602 |

The hand evaluation explains 41% of the target variance; the plain nets explain 74% and still
lose in play, which is the off-distribution point above in one line.

## Training

`768 → 256 → 32 → 1`, Adam lr 1e-3, batch 16384, 60 epochs, **`--l1-clip 3.8`** so every epoch
exports at qa=256. 22.7 s/epoch, 22.8 min.

| epoch | train | val |
|---|---|---|
| 1 | 0.017805 | 0.016417 |
| 10 | 0.014946 | 0.015090 |
| 20 | 0.014663 | 0.014840 |
| 30 | 0.014528 | 0.014739 |
| 40 | 0.014449 | 0.014670 |
| 50 | 0.014382 | 0.014548 |
| 60 | 0.014320 | **0.014504** |

Still falling at ~1.2e-5 per epoch. On par with the best plain net (0.014602 at 60 epochs,
0.014449 at 119) despite the weight clip, so the correction costs no accuracy on the lichess
distribution and buys the hand evaluation's behaviour everywhere else. Full curve in
`h256-52m-res-history.json`.

Sanity table after epoch 60, **as the correction in centipawns** (White to move):

```
start +45cp  |  +1 pawn (white) +27cp  |  +1 rook (white) +108cp  |  mate in 1 (white) +1007cp
```

Near zero for plain material, as expected. The +1007 on mate in 1 is the net saying the hand
score under-rates a queen next to a bare king; the total there is hand + 1007.

## Export

qa=256, qb=1024, qc=128, cp_scale=400, target=residual: headroom **6,157** (the clip bounds it
by construction, no epoch hunting); 273,645 bytes.

- `test_export`: **3.74 cp mean, 13.81 cp p99, 19.14 cp max** (tolerance 5 / 25); re-encode
  exact 1000/1000; mirror invariance 1000/1000. OK. The errors are on the correction, so they
  are the errors of the total.

## Commands

```bash
uv run python -m tools.nnue.hand --data tools/nnue/data/lichess-48m \
  --out tools/nnue/data/lichess-48m-hand --engine-dir <dir with fastboard.py, fasteval.py> \
  --verify <lichess .jsonl.zst> --verify-count 20000
uv run python -m tools.nnue.train --data tools/nnue/data/lichess-48m-hand --target residual \
  --epochs 60 --hidden 256 --l1-clip 3.8 --checkpoints tools/nnue/checkpoints-h256-res
uv run python -m tools.nnue.export --checkpoint tools/nnue/checkpoints-h256-res/epoch_060.pt \
  --out weights/nnue-h256-52m-res.npz --qa 256 --qb 1024
uv run python -m tools.nnue.test_export --weights weights/nnue-h256-52m-res.npz \
  --checkpoint tools/nnue/checkpoints-h256-res/epoch_060.pt
```
