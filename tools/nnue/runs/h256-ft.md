# nnue h256-ft — `weights/nnue-h256-ft.npz` (fine-tuned on positions from our own games)

The 163M-position net ([h256-100m-e71](h256-100m-e71.md)) fine-tuned for 12 epochs at lr 1e-4
on positions a search actually reaches. Pipeline commit 236d676 (adds `--init`; fixes the pgn
replay root in `data.py`, without which every one of our games was replayed from the wrong
position).

## Why

Every net trained on lichess predicted Stockfish better than the shipped one and played no
better. The engine session's diagnosis was that lichess analysis-board positions are not the
positions our search reaches. Measured directly, that is true and large:

| net | lichess (300k) | Stockfish self-play (300k) | **our games, held out (32,782)** |
|---|---|---|---|
| e60, shipped | 0.014583 | 0.014818 | 0.013781 |
| e36, 163M | 0.014716 | 0.012030 | 0.012144 |
| e71, 163M | 0.014664 | 0.012010 | 0.011950 |
| **ft, this file** | 0.015355 | — | **0.009453** |

Mean-predictor loss on the held-out set 0.058336. The fine-tuned net is 31% better than the
shipped net on positions from our own games it never saw, at the cost of 5% on lichess.

## Data

- **Our games:** every position from the 1,386 arena and rated PGNs on the M5 (v3.x to v4.4
  against frozen versions, Sunfish and fixed-depth Stockfish, 10 s to 120 s controls), skipping
  the first six plies and checks, labelled by Stockfish 19 at 20,000 nodes: 163,909 positions,
  cp mean +41, std 658. Split 80/20 by row order (games are contiguous): 131,127 train,
  32,782 held out in `tools/nnue/data/ourgames-test`.
- **Stockfish self-play** (`data.py selfplay`, depth-4 play with 25% random moves, 20k-node
  labels, a-h mirrors): the first 2,000,000 rows of a 5M run.
- **Lichess:** 2,000,000 rows (four shards of `lichess-48m`) so the net does not forget.
- Mix: our-games train rows repeated 4x (524,508) + 2M self-play + 2M lichess = 4,524,508
  rows, 2% validation split.

## Training

`--init` from e71, Adam lr 1e-4, batch 16384, 12 epochs at 5 s each, `--l1-clip 1.9`.

| epoch | train | val (mix) |
|---|---|---|
| 1 | 0.011848 | 0.011328 |
| 6 | 0.010409 | 0.010562 |
| 12 | 0.009812 | **0.010277** |

Still falling at 12; patience never fired. Full curve in `h256-ft-history.json`.

Sanity table after epoch 12, with the two parents (White to move):

```
ft   start  +6cp  |  +1 pawn +169cp  |  +1 rook +793cp  |  mate in 1  +676cp
e71  start  +5cp  |  +1 pawn  +98cp  |  +1 rook +515cp  |  mate in 1  +637cp
e60  start +29cp  |  +1 pawn  +83cp  |  +1 rook +435cp  |  mate in 1 +2005cp
```

**The scale grew.** Engine-played positions are more decisive than lichess ones (self-play
label std 1094 against 831), and the fine-tune learned that: a rook now reads +793 where the
hand evaluation says +500. In the blend `(hand + net) / 2` that is a leaf of about +646 for a
rook instead of +467. Material ordering is unchanged and contempt reads the hand evaluation
only, so nothing reads a constant against it, but it is the first file whose scale differs
from the hand evaluation's, and the bench should say whether that matters.

## Commands

```bash
uv run python -m tools.nnue.data selfplay --pgn-dir ~/pgn --positions 400000 --per-game 300 \
  --nodes 20000 --out tools/nnue/data/ourgames
uv run python -m tools.nnue.data selfplay --positions 5000000 --workers 12 --nodes 20000 \
  --per-game 30 --mirror --out tools/nnue/data/sfplay
# split ourgames 80/20 into ourgames-split/{train,test}.npz; symlink train x4, sfplay[:4],
# lichess-48m[:4] into tools/nnue/data/ftmix
uv run python -m tools.nnue.train --data tools/nnue/data/ftmix --checkpoints tools/nnue/checkpoints-ft \
  --epochs 12 --hidden 256 --init tools/nnue/checkpoints-h256-100m/epoch_071.pt --lr 1e-4 \
  --l1-clip 1.9 --patience 4
uv run python -m tools.nnue.export --checkpoint tools/nnue/checkpoints-ft/epoch_012.pt \
  --out weights/nnue-h256-ft.npz --qa 512 --qb 1024
uv run python -m tools.nnue.test_export --weights weights/nnue-h256-ft.npz \
  --checkpoint tools/nnue/checkpoints-ft/epoch_012.pt
```

## Predicted Elo, written before the bench

On the 32,782 held-out our-games positions, with the hand evaluation computed by
`tools.nnue.hand` (fasteval at prod 8b0d4d0):

| evaluator | loss |
|---|---|
| hand evaluation alone | 0.021436 |
| blend hand + e60 (v4.4) | 0.013847 |
| blend hand + e71 | 0.013013 |
| blend hand + ft | 0.011377 |
| blend hand + 0.5 x ft | 0.016080 |

The one calibration point is v4.0: the e60 blend over the hand evaluation alone measured
+243 Elo over 96 games, for a loss drop of 0.007589 here, so about 32 Elo per 0.001 of loss on
this set. The check: the same slope predicts +27 for the e71 blend over v4.4, and the pooled
218-game bench of that family measured about +32. **Prediction for this file: about +80 Elo
over v4.4**, roughly +55 to +105 given the +-60 on the calibration point. Two caveats: the e60
blend predicts these positions no better than e60 alone yet played 350 Elo better than the bare
net, so averaging buys something MSE does not see; and halving the net's share to offset its
larger scale makes the loss worse, so the file should be benched as exported.
